The uncomfortable question

Your policy may be correct.
Your application might still ignore it.

Policy evaluation tests prove the engine returns the right answer. AuthFault tests whether your application actually enforces that answer.

The bug it finds

A correct decision.
An ignored result.

The authorizer returns deny, but one missing check lets the operation continue. AuthFault changes the decision during testing and notices that nothing changes.

How it works

Three steps. One hard answer.

Instrument your authorization boundary once. AuthFault observes decisions, creates targeted faults, and reruns only the tests that touched them.

  1. 01
    ⌁

    Observe

    Record the allow and deny decisions your existing tests exercise.

  2. 02
    ⇄

    Mutate

    Flip one observed decision at a time—allow to deny, or deny to allow.

  3. 03
    !

    Find survivors

    If the tests stay green, you found an authorization enforcement gap.

authorizer.jsterminal
import { instrumentAuthorizer } from "authfault";

const authorize = instrumentAuthorizer({
  id: "project.delete",
  authorize: async ({ actor, project }) =>
    actor.role === "admin" ||
    actor.tenantId === project.tenantId
});
